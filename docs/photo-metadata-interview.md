# 사진 촬영 메타데이터 기반 인터뷰 단서

## 목적

사진 파일의 EXIF에 남아 있는 촬영 시각과 GPS 위치를 인터뷰 질문 생성의 보조 단서로 사용한다.

AI는 메타데이터를 확정 사실로 취급하지 않는다. 사용자가 직접 입력한 기억 단서가 가장 우선이며, 값이 충돌하거나 불확실하면 사진 번호를 지정해 확인 질문을 만든다.

## 데이터 흐름

1. 웹
   - 원본 파일을 Base64로 전송한다.
   - FastAPI가 Pillow로 EXIF를 읽는다.
2. iOS / Android
   - Expo ImagePicker를 `exif: true`로 실행한다.
   - 선택 결과의 EXIF 객체를 이미지 payload와 함께 전송한다.
   - 모바일에서 Base64가 재압축되어 EXIF가 사라져도 picker가 반환한 값을 사용할 수 있다.
3. FastAPI
   - 촬영 시각을 ISO 형식으로 정규화한다.
   - GPS의 도·분·초 또는 소수 좌표를 위도·경도로 정규화한다.
   - 인터뷰 프롬프트에는 사진 번호와 함께 최소 필드만 전달한다.
4. Gemini
   - 사용자 입력보다 낮은 우선순위의 기억 단서로 사용한다.
   - 원시 좌표를 사용자 질문에 그대로 노출하지 않는다.
   - 날짜·장소를 단정하지 않고 당시 사건, 동행, 방문 맥락을 확인한다.
5. 저장
   - 정규화된 결과를 `interviewData.photoMetadata`에 저장한다.
   - 기존 앨범 재인터뷰에서는 저장값과 사진 파일에서 다시 읽은 값을 합쳐 사용한다.

## 저장 예시

```json
[
  {
    "photoIndex": 1,
    "capturedAt": "2018-08-15T14:30:05+09:00",
    "location": {
      "latitude": 37.555,
      "longitude": 126.97806,
      "source": "exif"
    },
    "source": "photo_exif"
  }
]
```

## 수집하지 않는 정보

현재 단계에서는 인터뷰 생성에 필요하지 않은 카메라 제조사, 기기 모델, 렌즈, 촬영 설정 등은 저장하거나 Gemini에 전달하지 않는다.

## 제한사항

- 메신저나 SNS를 거친 사진은 EXIF가 제거될 수 있다.
- 스크린샷과 PNG에는 촬영 정보가 없는 경우가 많다.
- 카메라 날짜 설정이 잘못되어 있을 수 있다.
- GPS가 꺼져 있던 사진에는 위치가 없다.
- 좌표의 주소 변환은 현재 구현하지 않는다. Gemini는 좌표를 확정 장소로 단정하지 않고 확인 질문 생성에만 참고한다.
- iOS 카메라 촬영 결과는 Expo 정책상 GPS 태그가 포함되지 않을 수 있다.
- Android 전용 UI와 배포 설정은 후속 작업이며, 이번 변경은 Expo ImagePicker의 Android EXIF 반환 경로까지 호환한다.

## 테스트

```bash
cd backend
python -m pytest tests/test_photo_metadata.py tests/test_photo_metadata_prompt.py -q
```

직접 테스트할 때는 다음 경우를 각각 확인한다.

- 촬영 시각과 GPS가 모두 있는 JPEG
- 촬영 시각만 있는 JPEG
- EXIF가 없는 이미지
- 메신저에서 다시 저장한 이미지
- 사용자가 입력한 장소와 GPS 단서가 다른 이미지
- 같은 앨범을 다시 인터뷰하는 경우
